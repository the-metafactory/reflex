# Reflex Expansion — Appendix: The Reasoning Trail

> Companion to [reflex-expansion-thesis.md](reflex-expansion-thesis.md). The
> synthesis there is the conclusion; this is the full trail that produced it —
> the seed idea catalog, then all 8 agent transcripts verbatim (5 council, 3
> adversarial). Read this to audit *why* each idea landed where it did.

Method: ApertureOscillation (seed ideation across tactical/strategic/meta
apertures) → Council (5 composed personas, parallel, one round each) → RedTeam
(3 attackers on the synthesized thesis). Each agent received the same grounded
context (Reflex = activation runtime: Impulses `schedule|bus|http|manual` →
blueprints → guards `cooldown/run_lock/idempotency` + policy `auto|approval|
disabled` → fire → run in Pulse via cortex bridge; v0 `where` matcher is flat
top-level field-equality only).

## 0. Seed idea catalog (oscillated)

The candidate set the council and red team reacted to. Generated by oscillating
the aperture — narrow/tactical dev-loop wins, wide/strategic ecosystem bets,
then meta (Reflex's own development).

**Tactical (narrow aperture — concrete dev-loop wins):**
- **T1** issue auto-triage on open
- **T2** CI/test-failure → spawn fix-it assistant / draft PR
- **T3** dependency-bot PR → deterministic checks → approval → auto-merge
- **T4** stale issue/PR daily sweep
- **T5** tag pushed → release-notes process
- **T6** nightly security/dep audit → Discord
- **T7** PR merged → docs regen + deploy
- **T8** deploy failure → rollback / alert

**Strategic (wide aperture — ecosystem-level, Reflex as load-bearing tissue):**
- **S1** universal dead-man's-switch / heartbeat watchdog ("X should have happened by now")
- **S2** cross-repo fan-out (1 event → many target runs)
- **S3** org-wide human-approval / consent gateway for the whole agent fleet
- **S4** single cadence engine — migrate all scattered cron/launchd rituals onto Reflex's clock
- **S5** activation-decision ledger as audit / observability substrate
- **S6** external-signal activations (RSS / threat-feed / price → research run)
- **S7** progressive / canary rollout
- **S8** (surfaced by the strategist mid-debate) reactive feedback loop — Pulse run outcomes flow back as Impulses

**Meta (Reflex's own development):**
- **M1** dogfood Reflex's own CI/release through blueprints
- **M2** blueprint-authoring assistant (PR touching `activation/*.yaml` → validate vocab + dry-run + boundary check)
- **M3** fix the flat-matcher expression-language gap
- **M4** dry-run as a first-class ecosystem test harness

## 1. Council — THE OPERATOR (solo builder, capacity-constrained)

### Top 3 picks (ranked)

**1. S4 — Cadence engine (migrate scattered cron/launchd rituals onto Reflex's clock).**
Leverage/maint: very high / near-zero. Pure subtraction — `schedule`+`process`
already LIVE (build-journal). Every standup/briefing/timesheet ritual collapses
onto ONE clock with ONE decision ledger. No new matcher gaps, no nested fields,
no auth surface. New ritual = a spec file. This *reduces* babysitting. The "no
to a good thing is a yes to myself" pick.

**2. T5 — Tag pushed → release-notes process.** High / near-zero. Deterministic
`process`, flat `where` on tag ref handles it natively, no LLM nondeterminism,
no merge authority. Fires rarely, fails loud, output is a draft I review.

**3. T6 — Nightly security/dep audit → Discord.** High / low. Same shape as the
LIVE issue→Discord path. Read-only, no write authority, capacity-aware (Discord,
not inbox). Aligns with the day job. Worst case it's silent.

### KILL outright

- **T3 dep-bot → auto-merge.** Trust gate lives in nested PR-author/check fields
  the v0 flat matcher *cannot read*. Pushing safety into cortex and trusting
  auto-merge to main unattended. One bad merge = a day of cleanup.
- **S3 org-wide approval gateway.** Makes Reflex load-bearing for the WHOLE
  fleet — single point of failure that, offline-on-the-edge, blocks every agent.
  Maximum coupling, minimum leverage.
- **T2 CI failure → fix-it assistant.** Nondeterministic LLM firing on every
  flaky test = a queue of half-baked PRs to triage. Manufactures work disguised
  as automation.

### Non-obvious pick (not listed)

**Reflex self-watchdog on its OWN fires.** A schedule blueprint asserting "the
Sunday journal / nightly audit *did* fire," pinging Discord if the ledger shows
no event. Cheap (reads the immutable decision store already there). The one thing
a solo operator actually fears: silent automation that quietly stopped months
ago. Catches the failure mode the other picks introduce.

### Sharpest disagreement

The "make Reflex load-bearing" strategist wants centrality (S3, S2, M1). I say:
**load-bearing = single point of failure for a one-person team.** Leverage comes
from Reflex staying *peripheral and additive* — it INITIATES, never
orchestrates. The moment the release pipeline or approval flow *can't proceed
without* Reflex, a cron I understand is traded for a dependency I must babysit.
Keep it fireable, optional, boring.

## 2. Council — THE BOUNDARY ARCHITECT (DDD purist)

> Reflex INITIATES; it never orchestrates. Judged against that line.

### Boundary violations — orchestration/policy/cancellation smuggled in

- **T2 CI-failure→fix-it** — "fix-it" run is fine to *fire*, but the implied
  wait-and-retry loop is orchestration. Fire-and-forget only; if it loops, Pulse.
- **T3 dep-bot→checks→approval→auto-merge** — flagrant. A `checks→approval→merge`
  pipeline is orchestration = Pulse. Reflex fires ONE event, not a chain.
- **T7 PR-merged→docs+deploy** — sequential `docs THEN deploy` is orchestration.
  Reflex may fire two events; it must not *sequence* them.
- **T8 deploy-fail→rollback** — rollback is cancellation/compensation = Cortex.
- **S2 cross-repo fan-out** — 1 event→many targets is multi-target orchestration.
  Reflex resolves ONE target per decision.
- **S3 consent gateway** — org-wide policy ≠ activation policy (see below).
- **S4 single cadence engine** — "engine for all rituals" smuggles
  scheduling-as-a-service. Reflex *consumes* `schedule` Impulses; it is not a
  cadence *authority*.
- **S7 canary/progressive** — staged rollout = Pulse. Textbook orchestration.

### Clean fits — strengthen the pure activation identity (Top 3)

1. **S5 decision-ledger as audit substrate** — Decisions are already
   immutable+stored. This *names* an existing strength. Pure honesty.
2. **T5 tag→release-notes** — single Impulse, single fire, deterministic process
   target. Archetypal activation.
3. **S1 dead-man's-switch** — a missing-Impulse watchdog is pure rule eval over
   the schedule kind. Fires an event; orchestrates nothing.

(M4 dry-run + M1 dogfood are healthy too, but not activation primitives.)

### M3 flat-matcher gap — RULING

**Healthy deepening, *bounded*.** The pr-review blueprint bleeding its
author-gate into cortex is a real wound — but the cure is not an expression
language. That is the slope to an embedded rules engine, and a rules engine IS
policy evaluation = half of Pulse's reason to exist. **Permit:** nested-field
equality + negation (`not`). **Forbid:** boolean composition, arithmetic, regex,
anything Turing-curious. If a matcher needs a parser, the gate belongs downstream.

### S3 consent gateway — RULING

**Different bounded context wearing Reflex's skin.** `policy(approval)` exists —
but that is *per-decision* approval of ONE activation. "Org-wide consent gateway"
is standing authority over many actors/repos = governance = Spawn (Runtime
Policy) territory, or a net-new Governance context. Reject the rename.

### ONE structural term the ecosystem needs

**`ActivationChain` — explicitly OWNED BY PULSE.** The instant T2/T3/T7 demand
"then," someone crams sequencing into a blueprint. Name the seam now: Reflex
fires an `ActivationEvent`; any *ordered* multi-step reaction is an
`ActivationChain` that Pulse orchestrates. The vocabulary makes the violation
un-sneakable.

## 3. Council — THE ECOSYSTEM STRATEGIST (network effects, load-bearing)

### Load-bearing bets

**S5 — decision-ledger audit substrate.** Reflex already mints immutable
Decisions. Expose that ledger as the queryable source of truth for "why did
anything fire, ever." Every new automation gets observability for free; every
other component starts *reading* Reflex. Once they read you, they depend on you.
Tissue, not tool.

**S2 — cross-repo fan-out (1 event→many targets).** The multiplier on every
blueprint. Value of an Impulse goes superlinear with targets. One event lighting
up sage + docs + Discord + ragent → authors stop writing N blueprints and write
one. Fan-out turns Reflex from router into switchboard.

**S4 — single cadence engine.** Kill every scattered cron/launchd/CF-schedule.
Once all rituals share one clock, the ledger (S5) becomes *complete* and you own
temporal coordination. Mundane, but it's the land-grab.

### Killer sequencing

```
M3 (fix flat-matcher)
   └─► S2 (fan-out)  ──► S5 (ledger substrate) ──► S6 (ragent bridge)
   └─► S4 (cadence)  ──┘
```
**M3 ships first.** Flat top-level equality can't express "this repo AND
label=bug AND not-bot" — every interesting fan-out and triage rule dies on it.
The matcher is the gate; everything downstream is bottlenecked behind it.

### Moat vs cron-with-vocabulary

Honest: schedule+http+manual alone = cron with a nicer dictionary. The moat is
the **bus Impulse + immutable decision ledger + policy/guard layer**. Cron can't
observe NATS, can't enforce cooldown/idempotency/run-lock, can't tell you *why
it didn't fire*. "Didn't fire, here's the decision record" is the defensible
thing. Lean into negative-space observability — nobody else records non-events.

### Biggest strategic idea nobody proposed

**Reflex-as-feedback-loop (S8): Activation Events that fire on Reflex's own
ledger / on Pulse outcomes.** Outcomes (run succeeded/failed) flow back as
Impulses. Reflex stops merely initiating and becomes the substrate for
*reactive* automation (run-failed→retry, decision-rate-spike→alert).
Self-referential ledger = a control plane, not just a trigger plane.

### Real bottleneck

**The matcher (M3).** Fan-out, triage, consent-gateway, self-feedback all need
nested-field + negation + basic expression eval. Flat equality is the ceiling on
the entire strategic vision.

## 4. Council — THE SECURITY ADVERSARY (blast radius, attack surface)

### Top 5 attack scenarios (ranked)

**1. T3 dep-bot→AUTO-MERGE poisoning.** Spoof/compromise dependabot
(display-name forgery, or a real malicious dep version that passes checks) → PR →
green checks → auto-merge → arbitrary code in `main` → T7 auto-deploys it → RCE
in prod. Likelihood HIGH (dependency confusion + bot-impersonation are
commodity). Fix: gate on `sender.type=="Bot"` AND verified app-id (not display
name), pin check-suite IDs, lockfile-only diff.

**2. T7 PR-merged→DEPLOY via merge-as-trigger.** Attacker needs only *something*
to merge attacker content (chain #1 or a confused reviewer). Blast: public-site
RCE/defacement, secret exfil from Worker env. Fix: deploy from pinned ref + build
provenance; deploy policy=`approval` always; verify commit signature.

**3. build-journal process replay/injection.** Schedule impulse is internal
(good), but the process git-pushes+deploys a PUBLIC site unattended; if content
is generated from repo/issue data, injected markdown → stored XSS / malicious
links. Fix: sanitize/escape generated content; sandboxed origin; CSP.

**4. T8 deploy-fail→ROLLBACK as a downgrade primitive.** Induce a deploy
"failure" → rollback to an older, vulnerable version → re-introduces patched
CVEs. Fix: rollback only to a known-good allowlist; never across a
security-tagged release; alert + approval.

**5. S6 external-signal→research.** Attacker controls a feed item → fully
untrusted text → LLM with tool access → prompt-injection. Likelihood HIGH (feeds
trivially attacker-influenced). Fix: treat 100% of feed content as
`<untrusted-content>`, data-only, no tool-use (or read-only tools) in the session.

### Confused-deputy / prompt-injection

Exploitable **today**: PR→sage review takes untrusted external PR bodies/diffs
into an LLM with write-ish capabilities. Quarantine `<untrusted-content>` is
mitigation-by-prompt — *defeatable*; PR **diff content** (not just body) is the
smuggling channel. Wideners: T1 triage, T2 fix-it (logs are
attacker-influenceable), S6. Each adds an untrusted→LLM-with-write edge. Fix:
read-only by default; writes require a separate deterministic/approval step —
never let the injected session perform the privileged action.

### Replay / idempotency / cooldown

`cooldown:10s` + idempotency is **NOT enough**. Idempotency dedupes *identical*
deliveries; an attacker replays with a fresh delivery-id / re-signed body (valid
HMAC over same payload) → new key → fires again. Cooldown only throttles a 10s
window — replay at 11s sails through. Failure mode: N legit-looking fires = N
auto-merges/deploys. Fix: idempotency keyed on **payload content hash + event
identity** (not delivery-id), long TTL; reject seen `X-GitHub-Delivery`; bound by
event-time freshness window.

### Org-wide HMAC + flat-matcher + cortex-trust-gate — one bypass

Gate lives downstream in cortex on a flat field-equals of `sender.login`.
**Bypass:** forge `sender.login` to a trusted skip-list name while the *actual*
author differs — the flat matcher reads top-level `sender.login`, but GitHub
payloads also nest author identity (`pull_request.user`, commit author). Mismatch
between the field the gate trusts and the field that grants write = trust-gate
evasion. Fix: gate on cryptographically-bound identity (verified app-id / commit
signature), not a payload string.

### The one idea that must NEVER ship `policy: auto`

**T3 (dep-bot→AUTO-MERGE).** The only candidate where an untrusted, replayable,
bot-impersonatable impulse terminates in a write to `main` with no human in the
loop — and chains into T7/T8 deploy. Ship as `policy: approval`, always.

## 5. Council — THE YAGNI SKEPTIC (ruthless minimalist)

### Solutions looking for a problem (1-2 person scale)

- **S3 consent gateway** — there is no "org." One human. A consent gateway for an
  audience of one is a login screen guarding an empty room.
- **S4 single cadence engine** — you have *one* recurring job. A cadence *engine*
  for one cadence is the costume in its purest form.
- **S5 decision-ledger substrate** — Reflex *already* stores immutable decisions.
  A separate audit substrate audits the auditor. Who reads it? Nobody.
- **S7 canary / S1 dead-man's-switch / T8 rollback** — presuppose production
  traffic and blast radius a 2-person ecosystem doesn't have. You'll notice
  breakage because you're the only user.
- **T6 nightly audit, T4 stale sweep** — busywork generators. Stale what? 3
  blueprints.
- **M2 blueprint-authoring assistant** — you've authored 3 blueprints total.
  Tooling the thing you do four times a year is procrastination with a roadmap.

### Survivors of "what breaks if we DON'T build it?"

- **M3 fix flat-matcher** — *real.* The flat matcher is a hard ceiling: half the
  candidates (T1/T2/T7) can't be expressed without richer matching. Caps the
  whole product.
- **T1 triage** — the one job with genuine recurring human toil. Don't build it,
  you keep hand-sorting.
- **M4 dry-run harness** — cheap insurance. A misfiring auto-policy blueprint
  with no dry-run is how a solo builder spam-pings their own Discord at 3am.

### Is Reflex over-engineered? Verdict: YES, but barely paying rent.

- *Against:* the banned-words glossary, Myelin envelopes, 6-outcome taxonomy,
  "friendly surface canonical core" for **3 blueprints** is
  ceremony-per-payload that would embarrass a startup with 100x the users.
- *For:* the **F-6 bridge + guards (cooldown/run_lock/idempotency)** is genuinely
  load-bearing — it stops a webhook storm from double-firing real actions.

### Costume cases (cron + 10 lines wins)

T5, T3, build-journal — all a GitHub Action or `cron + gh CLI`. T4/T6 — `cron +
a script`. Reflex earns the wrapper *only* when a job needs `policy=approval` or
idempotency under burst. Everything fire-and-forget is a costume.

### Cheapest version of the most valuable idea (T1 triage)

80/20: **one blueprint, `issue.labels == []` → post to a `#triage` Discord
channel with title + link.** No LLM classification, no auto-labeling, no
taxonomy. Reuses the existing GitHub→Discord path. One afternoon; covers 80% of
the pain. Add matching/auto-label later — only if hand-triage actually hurts.

## 6. RedTeam — ATTACK THE ROADMAP

### 1. The "matcher-fix FIRST" trap — angle (b) is the bigger danger

**(a) Unstable equilibrium:** "nested equality + negation, no expression
language" holds until the first gate needs `OR`. Triage wants "unlabeled OR
labeled needs-triage" — one disjunction, "just two rules." Then a watchdog wants
"fired-count < 1" — now comparison operators. Each is a 20-line PR with an
unarguable use case. You don't decide to build a rules engine; you accept six
"obvious" PRs and discover you've built a bad one with no grammar, no precedence,
no test corpus. The line is held by a parser you refused to design — so it fails
open.

**(b) False-confidence trap is worse.** The matcher's headline payoff is gating
on nested fields like `sender.author_association == "OWNER"`. Those fields arrive
in webhook JSON the sender controls or can spoof. You're building a *security
control* on *attacker-supplied data*, and the matcher fix makes it *feel*
rigorous precisely when it's forgeable. (a) gives tech debt; (b) gives a guard
you'll *rely on* that a crafted payload walks through.

### 2. Self-watchdog: security theater

Yes. Silent-failure: the weekly-journal job fails to fire because the bus/cortex
bridge is wedged — the same substrate the watchdog's schedule impulse runs on.
Watchdog never wakes, no alert. Assurance exactly when things are fine, silence
in the correlated-failure case that matters. A co-located watchdog catches narrow
failures while blinding you to systemic ones. Real watchdog = out-of-band:
external cron / uptime pinger not sharing Reflex's runtime.

### 3. Sequencing / opportunity cost

Triage is the only step with stated real payoff and it **needs none of the
matcher work** — flat-field `label == null`, v0 already does it. Matcher-first
makes the one shippable win wait behind a parser project with no natural stopping
point. Invert: ship triage now on v0, let real misfires define which matcher
extension is load-bearing. Matcher-first is speculative generality dressed as
unblocking.

### 4. Ledger-as-substrate: the coupling trap

Once Cortex/Pulse read the ledger, its **schema becomes a public API you can't
migrate**. A field rename breaks two consumers silently → versioning, back-compat,
contract tests you didn't sign up for. "Everyone reads you" isn't a moat — it's
an inability to change. Worse: read-coupling is a *hidden* dependency (no import,
no call graph), so blast radius is invisible until it fires.

### 5. Steelman (survives the attack)

Invert the order, narrow the scope: **ship triage on the v0 flat matcher this
week**, then **the dry-run harness immediately after** (the genuinely
load-bearing piece — makes every future blueprint safe to change). Defer the
matcher until a real misfire names the specific extension, then add only that
one, with a written non-goal and a test corpus — as a security-sensitive parser,
never an author-trust gate on attacker-controlled fields. Replace the
self-watchdog with an **out-of-band** external pinger. Keep the ledger immutable
and **publish a frozen, versioned view** if others must read it. Payoff-first,
insurance-second, matcher-on-demand, watchdog-external, ledger-contracted.

## 7. RedTeam — NULL HYPOTHESIS (Reflex should NOT expand)

### 1. The premise is backwards reasoning

"Find more uses for Reflex" is solution-in-search-of-a-problem — Maslow's hammer
/ sunk-cost rationalization. You don't enumerate uses for a tool you need; you
reach for a tool because a problem bit you. Brainstorm-20-then-council
*manufactures* demand: the output is, by construction, things Reflex *could* do,
never pains you *have*. Scale mismatch: **3 blueprints, 1 user**, governed by a
6-outcome taxonomy, banned-words glossary, Myelin envelopes. A constitution for a
city-state running a household of three.

### 2. Opportunity cost: freeze it, call it done

Your own value: *"a no to a good thing is a yes to myself."* Every hour expanding
Reflex is an hour not shipping value. **"Done" = the three blueprints run
reliably, the matcher stays flat, the glossary stops growing.** Reflex is
plumbing — its value is invisible when it works, only ever negative when it
breaks. Frozen plumbing accrues zero maintenance debt, zero new failure surface.
Expansion is all downside on a component whose best day is silence.

### 3. Ecosystem smell: world-building vs shipping

Harsh: Reflex, Pulse, Cortex, Spawn, Myelin, Soma, sage/luna/echo — reads like a
mythology, not a product. Naming things gives the *dopamine of progress* without
the risk of a user saying "this is broken." Infrastructure exists to support more
infrastructure; the leaf nodes that touch reality (Discord pings, a code review,
a journal post) are thin. **The one diagnostic question:** *In the last 30 days,
how many of these components changed because an external user/outcome demanded it
— versus because building them was satisfying?* Mostly the latter = world-building.

### 4. The one defensible new capability

**A dead-man's-switch / health impulse** — fire when an *expected* impulse fails
to arrive. Passes the necessity bar because silent failure is the one thing the
current 3 blueprints cannot detect themselves, and a solo builder has no ops team
to notice. Everything else is elegance/optionality/symmetry, not a pain that drew
blood.

### 5. Concession: where expansion is RIGHT

- **The generic `process` handler already shipped** (cortex#1188): adding a
  blueprint is a config file, not a release. Marginal cost of use #4 is near-zero
  — "freeze" overstates the cost side.
- **Three live, e2e-verified uses is product-market fit with yourself.** A tool
  used three times unprompted has earned the right to a *small*, demand-pulled #4
  — when a real pain arrives, not when a brainstorm invents one.

## 8. RedTeam — COMPOUND / EMERGENT FAILURE

### 1. Feedback loops — the cross-blueprint storm

**Cycle:** `nightly-audit` fires → process runs → emits
`pulse.run.completed{outcome:fail}` → **self-watchdog** (bus) or triage matches →
fires a run that opens a GitHub issue → `issue→Discord` fires → issue-creation
emits its own `pulse.run.*` → watchdog re-evaluates → fires again. **Why safe
alone:** cooldown + run_lock are *per-blueprint*; A→B→A never trips either. The
loop lives in the *edges between* blueprints, which no guard owns. **Blast:**
unbounded run amplification — Pulse saturates, Discord rate-limits, GitHub spam.
Richer matcher makes it *worse*. **Breaker:** stamp every fired run with
`causation_depth`; global guard drops impulses with depth > N (~3). One field,
one comparison, kills all cross-blueprint cycles.

### 2. Dual-brain split

Both daemon and edge worker hold the `schedule` blueprint; both wake at the cron
tick. Idempotency is keyed `(blueprint, impulse)` — but the two brains write to
**different ledgers** (SQLite vs KV), so neither sees the other's record.
build-journal git-pushes+deploys a public site **twice** → deploy race / double
publish. **Breaker:** schedule impulses claim a **shared lease** before firing;
the loser no-ops.

### 3. Watchdog false-negative — watching the wrong signal

Reflex records **FIRED**, not **SUCCEEDED**. Watchdog sees `journal fired
Sunday`, reports all-clear — while the bridge crashed / git push 403'd / deploy
half-completed. **Public site silently stale for weeks; watchdog suppresses the
alarm it exists to raise.** It's watching the *intent* ledger, not the outcome.
Fix: assert on `pulse.run.completed{outcome}` (success within window), not the
fire record.

### 4. Guard-state corruption under hot-reload

Blueprint atomically swapped/renamed while an **approval is pending** or a
**buffered impulse** awaits run-lock release. Old id vanishes → its run_lock never
releases (orphaned lock blocks future fires), OR the buffered impulse
re-presents against the *new* blueprint of the same name with different policy —
an `approval`-gated action fires as `auto`. Worst: a renamed `disabled` blueprint
reloaded as `auto` drains its buffered queue unattended. Fix: on reload, drain/
cancel in-flight state for any id not present in the new set.

### 5. The one that bites — ranked #1

**Compound #1 + #3:** an audit/issue failure event triggers a self-reinforcing
run cluster, *and* the watchdog (reading fire-records) reports green throughout —
so the solo builder sees no alarm until rate-limits or the bill arrives. High
realism: all six survivors touch `pulse.run.>`, and the watchdog is the trusted
oracle. **Single cheapest fix:** make `pulse.run.completed{outcome}` the only
signal both watchdog and re-presentation consume — and carry `causation_depth` on
it. One enriched event (a) lets the watchdog assert *success* not *fire*, and (b)
gives the global depth-limit breaker its counter. Most leverage per line in the
whole system.

## How the trail produced the conclusion

The synthesis in the main doc is the intersection of these eight:

- **Triage = first matcher demand-pull, NOT a free win** ← YAGNI's 80/20 and
  RedTeam-1 both claimed triage "needs zero matcher work, flat `label == []`."
  **Both were wrong**, verified post-debate against `src/sources/bus.ts:207`:
  the matcher is strict `===` on *top-level* fields only; `issue.labels` is
  nested + an array, unreachable. Lesson: an adversary's confident mechanical
  claim still needs a code probe — neither the council nor the first red team
  checked it. The main-doc conclusion reflects the corrected mechanics (cortex
  label gate, or the bounded matcher extension), not this transcript's claim.
- **Matcher DEFER (demand-pulled)** ← RedTeam-1 rightly challenged the
  Strategist's "M3 first" consensus as speculative generality. The *direction*
  (defer, demand-pull) survives even though RedTeam-1's supporting example was
  wrong — triage is the demand that pulls the first extension.
- **Watchdog RE-SPEC (out-of-band, outcome-signal)** ← Operator's pick, repaired
  by RedTeam-1 (theater) + RedTeam-3 (false-negative).
- **`outcome + causation_depth` event** ← RedTeam-3's compound-failure fix,
  cross-validated against the Strategist's S8 feedback-loop vision.
- **KILLs (auto-merge, deploy-chain, rollback, fan-out, consent-gateway)** ←
  Boundary Architect's violations + Security's blast-radius ranking, unanimous.
- **`ActivationChain` (Pulse-owned)** ← Boundary Architect, the one new term.
- **"Keep yourself honest" diagnostic** ← Null-hypothesis attacker's concession
  question, the guard against the exercise's own bias.
